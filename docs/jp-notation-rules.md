# データベース 和文フィールド 記法ルール

> **対象**: Claude Code / GitHub Copilot / その他 AI 補完ツール  
> **目的**: 100BeautiesLab. Creations DB の全作品における JP フィールドの書式・記法を定義する基準書  
> **最終更新**: 2026-06-14  
> **関連ドキュメント**: [`localization-en-rules.md`](localization-en-rules.md)（英訳ルール）

---

## 0. 最優先原則

1. **既存の JP 値を上書きしない**: ユーザーが手動入力した値は AI が勝手に変更・再解釈しない。
2. **書式一貫性**: 同じキャラクターの同種フィールドは同じ書式で記述する。
3. **英訳との対応**: JP フィールドの区切り文字・行構造は EN フィールドに 1:1 で対応する。改行 `\n` の位置・数は JP と EN で揃える。

---

## 1. 共通記法

### 1-1. 区切り文字

| 記号 | 役割 | 使用例 |
|------|------|--------|
| `;` | **大分類区切り**（呼称フィールドでカテゴリをまたぐ） | `彼/彼女;[※名前呼び]` |
| `/` | **等価な代替候補**（文法的・意味的に等価） | `彼/彼女`、`~君/~さん` |
| `,` | **並列列挙**（同種だがニュアンスが異なる複数候補） | `*いつ,*れ`、`*いつ/*れ` |
| `\n` | **コンテキスト別バリアント**（状況・相手・場面によって使い分ける） | `彼/彼女;[※名前呼び]\n~先輩` |

区切り文字の優先度（呼称フィールド内の構造）:

```
\n（コンテキスト最大単位）
  └─ ; （カテゴリ区切り）
       └─ , / /（同カテゴリ内の代替候補）
```

**注意**: `/` と `,` は同優先度で混在することがある（例: `*いつ/*れ`、`*の子/*っち;[※名前呼び]`）。

---

### 1-2. プレースホルダー `~`

`~`（チルダ）は**名前プレースホルダー**。実際の名前（相手の名前、またはキャラ名）を表す。

```
~君     → (名前)君
~さん   → (名前)さん
~殿     → (名前)殿
~先輩   → (名前)先輩
~ちゃん → (名前)ちゃん
~クン   → (名前)クン（カタカナ版）
```

EN 対応: `~-kun`、`~-san`、`~-dono`、`~-senpai`、`~-chan`（チルダは EN でも保持）。

---

### 1-3. 指示代名詞系記号 `*xxx`

`*`（アスタリスク）+ 語幹は**指示代名詞バリアント全体**を表す省略記法。  
`*いつ` は「そいつ/こいつ/どいつ/あいつ」のすべてをカバーする。

| 記号 | 展開形 | 人称 | EN 目安 |
|------|--------|------|---------|
| `*いつ` / `*イツ` | そいつ/こいつ/どいつ/あいつ | 人称的・客観的両方 | `this/that/who/what/which/them (as personal or objective)` |
| `*れ` / `*レ` | それ/あれ/これ/どれ | 客観的のみ | `this/that/who/what/which/them (as objective)` |
| `*の子` / `*のこ` / `*っち` | その子/この子/どの子 / そっち | 人称的（informal） | `this/that/which kid (*no-ko)` |
| `*の人` / `*の者` | その人/その者 | 人称的（neutral〜formal） | `that/this person` / `that one (as personal)` |
| `*の方` | その方/この方 | 人称的（polite） | `that/this side/person` |
| `*奴(やつ)` | そいつ/あいつ | 人称的（rough） | `that/this/whom one` |
| `*ちら(の者)` | そちら（の方） | 人称的（very polite） | `that side/person there` |

---

### 1-4. 参照形式 `[※xxx]`

角括弧＋参照マーク（`[※]`）は**他フィールドや状況への参照**を示す定型形式。

| 参照形 | 意味 | EN 対応 |
|--------|------|---------|
| `[※名前呼び]` | 相手の名前で呼ぶ（どの名前かは状況依存） | `[*by name]` |
| `[※二人称]` | SecondPersonCalling と同じ呼称を使う | `[*second-person calling]` |
| `[※三人称]` | ThirdPersonCalling と同じ呼称を使う | `[*third-person calling]` |
| `[※その時により変わる]` | 固定した呼び方なし、状況依存 | `[*Varies depending on the situation]` |

---

### 1-5. インライン注釈 `※`

`※`（参照マーク）をスペース後に続けて**自由テキスト補足**を記載する。

形式:
```
(値) ※(注釈)
```

例:
- `~さん ※信頼している人に対して` → 「信頼している相手には~さんと呼ぶ」
- `ボク ※名前呼び` → 「自分のことを名前で呼ぶ」
- `貴殿(きでん) ※稀` → 「稀にこの形式を使う」
- `ウタカ ※毎回逆になる` → 「本来と逆の名前を使う」

**`[※]` との違い**: `[※xxx]` は定義済みの参照形式（値が決まっている）。`※ xxx` は自由記述の補足説明。

---

### 1-6. 読み仮名付き表記

名称フィールドや呼称に読み仮名・別読みを括弧付きで付記する場合:

- 全角括弧 `（ふりがな）` または半角括弧 `(ふりがな)` どちらも使用される
- 形式: `正式名（読み）` 例: `私(わたくし)`、`主(あるじ)`
- オプションバリアント: `旦那様（/奥様）` → `/` 前置で「奥様 はオプション」を表す

---

### 1-7. 非公開・不明値（hideText）

フィールドが非公開・未設定・不明な場合の定型値（`data/db_type.json > $VarsDef > #List_hideText` 定義）:

| JP（使用値） | EN |
|------------|-----|
| `？？？` | `????` |
| `データ無` | `No Data` |
| `公開不能` | `Openly Not` |
| `判定不能` | `Unjudgeble` |
| `判定失敗` | `Judgement Failed` |
| `検証中` | `Now Researching` |
| `極秘事項` | `Confidential` |
| `非公開希望` | `Non-Public at Pleasure` |
| `非公開` | `Non-Public` |
| `条件による` | `Depending on Conditions` |
| `定義不能` | `Undefineble` |
| `本人すら把握されていない` | `Not Aware` |
| `不定` | `Indefinite` |

## 2. 呼称フィールド (Calling Fields)

### 2-1. 共通構造

呼称フィールドの最大構造（ThirdPersonCalling を例に）:

```
[コンテキスト A（デフォルト / 一般的な状況）]
\n
[コンテキスト B（特定の相手や場面）]
```

各コンテキスト内の構造（ `;` で 3 分類）:
```
[代名詞系] ; [指示詞系] ; [名前・敬称系]
```

すべての分類が揃っているとは限らない。1 分類のみ（例: `[※名前呼び]` だけ）も正常。

---

### 2-2. ThirdPersonCalling（三人称）

このキャラが**他のキャラを**三人称でどう呼ぶか。  
**このフィールドはキャラ自身の代名詞ではない。**

#### フィールドの 3 分類

| 分類 | 内容 | 例 |
|------|------|-----|
| 代名詞系 | 標準的な三人称代名詞 | `彼/彼女`、`彼女`、`彼` |
| 指示詞系 | 指示代名詞（`*` 系）→ §1-3 | `*いつ`、`*れ`、`*の子`、`*の方` |
| 名前・敬称系 | 名前/参照形/敬称 | `[※名前呼び]`、`~君`、`~さん`、`~殿`、`~先輩` |

#### セミコロン区切りの例

```
彼/彼女;[※名前呼び]                → 代名詞 ; 名前
彼/彼女;*れ;[※名前呼び]            → 代名詞 ; 指示詞 ; 名前
彼/彼女;*れ;~くん/~さん             → 代名詞 ; 指示詞 ; 敬称
*イツ;[※名前呼び];~(な)ヤツ        → 指示詞 ; 名前 ; 形容詞的派生
*の子/*っち;[※名前呼び]            → 指示詞（2 種）; 名前
~殿/*イツ                           → 敬称/指示詞（等価な 2 択を / で区切る）
```

#### 複数コンテキストの例

```
彼/彼女;*れ;[※名前呼び]
ナンバーテールズに対して：先輩        → コンテキスト A \n コンテキスト B
```

```
*いつ,*れ;[※名前呼び]
~さん ※信頼している人に対して        → コンテキスト A \n 限定的コンテキスト B（注釈付き）
```

---

### 2-3. FirstPersonCalling（一人称）

このキャラの**自称**。

形式:
- 単一: `ぼく`、`おれ`、`わたし`、`私(わたし)`、`私(わたくし)`、`オイラ`、`ワイ`、`こっち`
- 複数（状況別、`\n` 区切り）: `自分\nおれ`、`オレ\nぼく(※ナイヴ時)`
- 名前自称: `ミル ※名前呼び`（キャラ名 ＋ 注釈）

---

### 2-4. SecondPersonCalling（二人称）

このキャラが**相手を**どう呼ぶか。

| 形式 | 例 |
|------|-----|
| 標準的な二人称 | `きみ`、`君(きみ)`、`あんた`、`お前`、`あなた`、`貴方(あなた)` |
| 敬称付き | `あなた様`、`貴殿(きでん)` |
| 複合・名前依存 | `旦那さん/奥さん`（相手の性別による） |
| 参照形 | `[※三人称]`（ThirdPersonCalling を使う）、`[※名前呼び]` |
| コンテキスト別 | `旦那さん/奥さん\nアンタ`（状況によって切り替え） |

---

### 2-5. ForMasterCalling（主人の呼び方）— NT 専用

このキャラが**主人（マスター）を**どう呼ぶか。NT 作品の固有フィールド。

| パターン | 例 |
|----------|-----|
| 役割語 | `主(あるじ)`、`先輩`、`センパイ` |
| 名前 ＋ 敬称 | `～先輩`、`～兄(にぃ)/～姉(ねぇ)` |
| 丁寧な敬称 | `旦那様（/奥様）`、`ご主人様（/お嬢様）` |
| 役割名 ＋ さん | `クライアントさん` |
| 参照形 | `[※その時により変わる]` |
| コンテキスト別 | `旦那様（/奥様）\nご主人様（/お嬢様）` |

---

### 2-6. For79thDealerCalling / For80thDealerCalling — FL 専用

FL 作品の特定の Dealer（錦野舞・錦野歌嫁）への呼称。

形式: 名前または名前 ＋ 敬称。注釈は `※` で付記。

```
舞(まい)       → 下の名前のみ
舞(まい)君     → 名前 + 君
舞             → 省略形
舞\n舞さん     → コンテキスト別（`\n` 区切り）
ウタカ ※毎回逆になる  → 名前 ＋ 注釈
```

## 3. テキストフィールド (Text Fields)

対象フィールド: `Character`、`Hobby`、`SpecialSkill`、`Favor`、`Unlike`、`Summary`、`Backgrounds`、`InStory`、`RelationNotes`、`NumerospecStats.NumerospecAbout`、`ConversationPattern` 内各フィールド、他

### 3-1. 改行 `\n`

複数のトピック・段落・箇条書き的な内容を並記する場合に使用。  
英訳の `_EN` フィールドでも同じ位置に `\n` を置いて対応する（行数を揃える）。

```
行動意欲が突出している怖いもの知らず
自分らしさを前向きに受け入れている
```
→ 2 行。EN でも 2 行。

---

### 3-2. 注釈・補足の書式

自由テキスト中の注釈は以下の形式で記述する:

| 形式 | 用途 | 例 |
|------|------|-----|
| `（※...）` | 伏せ字・検閲・情報隠蔽 | `（※検閲で削除されている…）` |
| `（...）` | 一般的な補足 | `（本人は気づいていない）` |
| `※ ...` | 行頭・行末の自由補足 | `※本人すら把握されていない` |

EN での対応:
- `（※検閲で削除されている…）` → `(* censored...)`
- その他の括弧補足 → 前後の文脈に合わせて英訳

---

### 3-3. セリフ・発言の表記

- セリフは `「」` で囲む（日本語標準）
- `♡`、`♪`、`☆`、`★` 等の絵文字は**原文のまま保持**（`♥` 等に変換しない）
- EN 翻訳でも絵文字はそのまま引き継ぐ

---

### 3-4. 口調・特殊表現

`TalkingTone`（口調）フィールドには以下のような自由記述が使われる:

```
標準的な口語体
物腰が柔らかく穏やか
丁寧語がベース、時折崩れる
```

EN 化: 同様の体言止め・形容詞句で統一。

---

## 4. 名称フィールド (Name Fields)

### 4-1. Name / FormalName

- `Name`（愛称）: 普段の呼び名。複数の名前がある場合は登録順に記載。
- `FormalName`（正式名称）: フルネーム・公式名称。
- 読み仮名は `（ふりがな）` または `(ふりがな)` で付記。

---

### 4-2. CodeName（コードネーム）

作品ごとに書式が異なる:

| 作品 | 書式 | 例 |
|------|------|-----|
| NT | 漢数字（1 桁ずつ独立） | `七〇`（= 7 と 0）、`六六`（= 6 と 6） |
| FL | カード系記号・番号 | `Ⅰ`、`0`、`大アルカナ 0` |

EN: NT の漢数字は 1 桁ずつ英語数詞にしてハイフン連結（`七〇` → `Seven-Zero`、`六六` → `Six-Six`）。`Seventy` 等の複合数詞は不正解。

---

## 5. 分類・列挙フィールド

### 5-1. GenderType（性別）

| 値 | 意味 | EN 代名詞 |
|----|------|-----------|
| `Neutral` | 中性（人間の性別概念外の存在） | `ze / zir / zirself` |
| `FemaleNeutral` | 女性的中性（女性寄りだが中性的） | `she / her` |
| `MaleNeutral` | 男性的中性（男性寄りだが中性的） | `he / him` |
| `Female` | 女性 | `she / her` |
| `Male` | 男性 | `he / him` |
| `Arbitrary` | 任意・設定なし | 代名詞を避ける |
| `Unknown` | 不明 | 代名詞を避ける |

詳細は [`localization-en-rules.md § 1`](localization-en-rules.md) 参照。

### 5-2. Progress（制作進捗）

値の定義は `data/db_type.json > $DefType > Progress > $EnumDef` 参照。  
外部の AI がこのフィールドを変更・追加しないこと（ユーザー管理）。
