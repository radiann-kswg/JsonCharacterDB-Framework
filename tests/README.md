# tests/

Vitest（`npm test`）。**フレームワーク本体の挙動**だけを検証します。

## ここに置くもの / 置かないもの

| 置く | 置かない |
| --- | --- |
| レンダラ・スキーマ解決・Service Worker ルーティング・ツールの単体テスト | 特定作品のキャラクター設定に対する回帰テスト |
| インメモリのフィクスチャで完結するテスト | 「レコードが 500 件以上ある」のようなデータ規模の前提 |
| `data/Works_Sample/` を読むテスト | 上流リポジトリ固有の作品ディレクトリを読むテスト |

上流 `100BeautiesLab_CreationsDB` にあった**実データ回帰テスト**（`Works_NumberTales` 等の
スキーマ移行・辞書内容を固定するもの）は、汎用フレームワークでは検証対象を持たないため取り除いています。

## 自分のデータに対するテストを足す

自分の作品DBを作ったら、`data/` を読む検証テストは**あなたのリポジトリ側で**追加してください。
そのまま使える汎用テストは同梱済みです。

| テスト | 何を守るか |
| --- | --- |
| `data.sanity` | `data/` 配下の JSON がすべてパースできる |
| `data.field-order` | フィールド順が `db_type.json` の宣言順に追従している |
| `data.image-links` | JSON が参照する画像が実在する（大小文字も一致） |
| `bilingual-fields` | `_JP` / `_EN` の対が欠けていない |
| `meta.catalog.schema` | `db_meta.json` のカタログ宣言が スキーマどおり |
| `docs.links` | ドキュメント内リンクが切れていない |

作品固有の不変条件（「この作品のキャラは全員 X を持つ」など）を守りたい場合は、
`tests/<yourwork>.data.test.js` のように**作品名を冠したファイル**で追加すると、
フレームワーク側の更新と衝突しません。
